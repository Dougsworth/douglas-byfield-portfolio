How I work

The same habits I use on finance software, applied to yours

  1. 01

    Start with the problem.

    What has to be true when this works? Fewer hours on invoices, more tickets sold, rent paid on time. That becomes the spec.

  2. 02

    Sketch before code.

    You see the flow on paper first, so we argue about the idea, not the pixels.

  3. 03

    Ship small, ship often.

    A working version early, then steady improvements you can click on. No big reveal at the end.

  4. the part most people skip

    04

    Built like production.

    Clean data, tests where they matter, security from day one. Payments, logins and forms that never leave anyone stuck halfway.

  5. 05

    I stay after launch.

    Fixes, new features and the last minute change before the big day. Your software keeps up with your business.
